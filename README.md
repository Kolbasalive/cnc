# CNC Telemetry

Сбор телеметрии со стендов ЧПУ, хранение в PostgreSQL и дашборд.

Фронтенд не хранит свои данные и не подставляет заглушки. Все экраны читают HTTP API, API читает базу, в базу пишет сборщик.

## Откуда берутся данные

```text
MQTT-брокер 91.240.87.171:1883
        \                         cnc.kovalev.team/get/3
         \                        cnc.kovalev.team/get/5
          \---- mqtt-reader ----/
                     |
                  PostgreSQL
                     |
                  Go API :8080
                     |
                  React :5173
```

Сборщик `mqtt-reader` подписывается на топики `demodata/#`, `sensor/#`, `cncmqtt/#`, `cnc/lathe/#` и раз в 5 секунд опрашивает стенды 3 и 5. Каждое MQTT-сообщение остаётся в `mqtt_messages` и одновременно раскладывается по смыслу: температура и влажность в `sensor_readings`, сигналы демо-токарного в `demo_lathe_signals`. Ответ стенда пишется в `cnc_status_snapshots`, оси в `cnc_axes`, блок ошибки в `cnc_errors`.

## Компоненты

| Каталог | Что это |
|---|---|
| `mqtt-reader` | Сборщик MQTT и HTTP |
| `api` | Чтение базы и JSON для фронта. Swagger: `http://127.0.0.1:8080/swagger` |
| `web` | Дашборд: обзор, стенд, MQTT, аналитика |
| `cnc-db` | PostgreSQL 16 в Docker и миграции |

## Таблицы

| Таблица | Что хранит |
|---|---|
| `stands` | Справочник стендов 3 и 5 |
| `mqtt_messages` | Сырой журнал MQTT: топик, текст, число, `received_at` |
| `sensor_readings` | Температура и влажность: `demodata`, `stand`, `demo_lathe` |
| `demo_lathe_signals` | `x`, `z`, `program`, `program_percent` демо-токарного |
| `cnc_status_snapshots` | Снимок стенда: время ядра и канала, статус, режим, программа, процент. `sections` и `payload` сохраняют разобранный и исходный JSON |
| `cnc_axes` | Положение осей этого снимка |
| `cnc_errors` | Ошибка этого снимка, если секция ошибки была в ответе |

`received_at` — время, когда запись принял сборщик. Время ошибки со станка лежит отдельно в `cnc_errors.reported_at`.

## Запуск

PostgreSQL, из каталога `cnc-db`:

```bash
docker compose up -d
```

Порт снаружи только `127.0.0.1:5432`. Миграции из `cnc-db/migrations` применяются при первом создании тома. На уже существующем томе они сами не переигрываются.

Сборщик и API, из каталога `cnc`:

```bash
./run.sh log
```

Скрипт читает `.env` и поднимает оба процесса. В логе должны появиться `MQTT SAVED` и `CNC SAVED`. Остановка: Ctrl+C и `./stop.sh`.

Фронт:

```bash
cd web
npm install
npm run dev
```

Открыть `http://localhost:5173`. Vite проксирует `/api` на `127.0.0.1:8080`.

## Дашборд

- **Обзор** — последние снимки стендов, климат, демо-токарный, активные ошибки. Обновление раз в 5 секунд.
- **Стенд** — статус, режим, программа, оси, доли времени, online/offline, журнал ошибок с температурой и влажностью.
- **MQTT** — список топиков и график выбранного.
- **Аналитика** — доступность стендов, программы демо-токарного, моменты равенства температуры и влажности.

Период на графиках и отчётах: 1 час, 6 часов или 24 часа. Это параметры `from` и `to` к API, не локальные массивы.

## Локальные демо-строки

`cnc-db/seed-demo.sql` можно загрузить вручную, если нужно посмотреть дашборд без живого брокера. Compose его не выполняет, фронтенд про него не знает. Скрипт вставляет выдуманные снимки в те же таблицы, поэтому после запуска сборщика на экране будут и они, и живые данные.
