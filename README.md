# CNC Telemetry Collector

Система сбора телеметрии с ЧПУ-станков через MQTT и HTTP API с
сохранением данных в PostgreSQL.

## Назначение

Приложение собирает два типа данных:

-   **MQTT** --- сообщения из подписанных топиков: например,
    температура, влажность, координаты осей и параметры выполнения
    программы.
-   **HTTP API** --- периодические снимки состояния станков № 3 и № 5:
    `https://cnc.kovalev.team/get/3` и `https://cnc.kovalev.team/get/5`.

Данные сохраняются для последующего анализа, построения графиков и
сопоставления показателей во времени.

  -----------------------------------------------------------------------
  Компонент                           Назначение

                                      топикам (topics)

                                      `cnc_status_snapshots` и индекс


## Модель базы данных

В базе две независимые таблицы. Между ними нет внешнего ключа: они
хранят разные типы телеметрии и сопоставляются при анализе по времени и
параметрам.

### `mqtt_messages`

Одна запись соответствует одному принятому MQTT-сообщению.

  -----------------------------------------------------------------------
  Поле                    Тип                     Назначение
  ----------------------- ----------------------- -----------------------
  `id`                    `bigserial`, PK         Уникальный
                                                  идентификатор записи

  `received_at`           `timestamptz`           Время получения
                                                  сообщения приложением

  `topic`                 `text`                  MQTT-топик, из которого
                                                  пришло сообщение

  `value_num`             `double precision`,     Числовое представление
                          nullable                payload, если его
                                                  удалось преобразовать в
                                                  число

  `value_text`            `text`                  Значение payload в
                                                  текстовом виде;
                                                  сохраняется для
                                                  числовых и текстовых
                                                  сообщений
  -----------------------------------------------------------------------

Индекс `mqtt_messages_topic_time_idx` по `(topic, received_at)` ускоряет
выборки истории конкретного топика за период.

** `value_num` и `value_text`.** `value_text` хранит значение
в универсальном текстовом виде. `value_num` заполняется, если значение
удалось разобрать как число. Тогда SQL-запросы могут использовать `AVG`,
`MIN`, `MAX` и числовые сравнения без повторного преобразования текста.
Например, для `23.7` оба поля будут заполнены; для `AUTO` `value_num`
будет `NULL`, а `value_text` сохранит `AUTO`.

### `cnc_status_snapshots`

Одна запись соответствует одному снимку состояния станка, полученному
через HTTP API.

  ---------------------------------------------------------------------------
  Поле                        Тип                     Назначение
  --------------------------- ----------------------- -----------------------
  `id`                        `bigserial`, PK         Уникальный
                                                      идентификатор снимка

  `stand_id`                  `integer`               Номер станка; ограничен
                                                      значениями `3` и `5`

  `received_at`               `timestamptz`           Время получения снимка
                                                      приложением

  `core_runtime_total`        `text`, nullable        Общее время работы ядра

  `core_runtime_current`      `text`, nullable        Текущее время работы
                                                      ядра

  `core_restarts`             `integer`, nullable     Количество перезапусков
                                                      ядра

  `channel_count`             `integer`, nullable     Количество каналов

  `channel_runtime_total`     `text`, nullable        Общее время работы
                                                      канала

  `channel_runtime_current`   `text`, nullable        Текущее время работы
                                                      канала

  `status`                    `text`, nullable        Статус канала, например
                                                      «Работа» или «Готов»

  `mode`                      `text`, nullable        Режим канала, например
                                                      «Авто»

  `program_time`              `text`, nullable        Время работы программы

  `program_percent`           `integer`, nullable     Процент выполнения
                                                      программы, если удалось
                                                      извлечь число

  `program_name`              `text`, nullable        Имя или путь
                                                      выполняемой программы

  `sections`                  `jsonb`                 Распарсенные параметры,
                                                      сгруппированные по
                                                      разделам API

  `payload`                   `jsonb`                 Полный исходный
                                                      JSON-ответ API
  ---------------------------------------------------------------------------

Индекс `cnc_status_stand_time_idx` по `(stand_id, received_at DESC)`
ускоряет выборки истории конкретного станка.

#### `sections` и `payload`

-   **`payload`** --- полный исходный JSON-ответ API. Он сохраняет то,
    что реально вернул сервер, и полезен для аудита, повторного разбора
    и проверки новых полей.
-   **`sections`** --- представление параметров в более удобной
    структуре: раздел API → название параметра → значение. Это позволяет
    работать с распарсенными данными, не разбирая каждый раз исходные
    массивы JSON.

Отдельные колонки (`status`, `mode`, `program_name`, `program_percent` и
другие) вынесены для удобных SQL-запросов. `sections` также сохраняет
параметры, для которых пока нет отдельных колонок, например перемещения
по осям. `payload` оставляет полный оригинал ответа.

## Примеры SQL-запросов

Последние MQTT-сообщения:

``` sql
SELECT received_at, topic, value_num, value_text
FROM mqtt_messages
ORDER BY received_at DESC
LIMIT 20;
```

Последние снимки состояния станков:

``` sql
SELECT stand_id, received_at, status, mode, program_name, program_percent
FROM cnc_status_snapshots
ORDER BY received_at DESC
LIMIT 20;
```

История конкретного станка:

``` sql
SELECT received_at, status, mode, program_name, program_percent
FROM cnc_status_snapshots
WHERE stand_id = 3
ORDER BY received_at DESC
LIMIT 20;
```

Среднее значение числового MQTT-топика по минутам:

``` sql
SELECT date_trunc('minute', received_at) AS minute,
       AVG(value_num) AS avg_value
FROM mqtt_messages
WHERE topic = 'demodata/temp'
  AND value_num IS NOT NULL
GROUP BY minute
ORDER BY minute;
```

## Запуск и проверка

### PostgreSQL

Из каталога `cnc-db`:

``` bash
docker compose up -d
docker compose ps
```

Подключение к базе внутри контейнера:

``` bash
docker exec -it cnc-postgres psql -U cnc -d cnc
```

В `psql` команда `\dt` показывает таблицы, `\q` завершает работу.

### Go-сборщик

Из каталога `mqtt-reader` приложение запускается согласно настройкам
проекта, например через `./run.sh`. Перед запуском должны быть настроены
`DATABASE_URL`, `MQTT_USERNAME` и `MQTT_PASSWORD`. Go сам по себе не
загружает `.env`: это должен делать скрипт запуска или другой механизм
конфигурации.

### Инициализация базы

Скрипты в `/docker-entrypoint-initdb.d/` официального образа PostgreSQL
выполняются автоматически только при первой инициализации пустого
каталога данных:

``` bash
docker compose exec -T postgres psql -U cnc -d cnc < add_cnc_status.sql
```

**Осторожно:** удаление Docker volume PostgreSQL приводит к потере
хранящихся в нём данных. Не используйте `docker compose down -v`, если
не планируете намеренно удалить базу.

## Примечания

-   `received_at` --- время получения данных приложением; это не
    обязательно timestamp события, сформированный самим станком.
-   В текущей версии HTTP API опрашивается с интервалом 5 секунд, если
    значение не менялось в коде.
-   Времена работы хранятся как текст, поскольку API возвращает
    длительности строками. Для аналитики их может потребоваться
    преобразовывать в секунды.
-   `sections` и `payload` намеренно частично дублируют информацию:
    первое поле удобно для работы с разобранными разделами, второе
    сохраняет оригинал ответа.
